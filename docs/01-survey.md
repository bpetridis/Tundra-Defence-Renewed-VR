# Survey of the shipped 1.04 release

What the original archive actually contains, established by reading the files directly.
Nothing here is guesswork — every figure below came from parsing the binaries.

## The archive

`Tundra Defense SSE v1.04-14310-1-04.zip`, 28,115,011 bytes, three files, all dated 2017-12-31.
Hashes in `original/SOURCE-ARCHIVE.md5`.

| file | size |
|---|---|
| `Tundra Defense SSE.esp` | 484,934 B |
| `Tundra Defense SSE.bsa` | 26,382,777 B |
| `Tundra Defense SSE - Textures.bsa` | 1,246,788 B |

## The plugin

| property | value |
|---|---|
| author | Aykan |
| masters | **`Skyrim.esm` only** — no DLC dependency |
| form version | **1.7** — a proper SSE conversion, not a raw LE port |
| records | 2,368 |
| ESM flag | no |
| localized | no — strings are embedded in the plugin |

No DLC masters and a correct SSE form version is a good starting point. A lot of 2017-era ports
were LE plugins renamed; this one was converted properly.

## The textures BSA

10 files, all LZ4-compressed, so the simple extractor skips them. Not currently a problem — the
textures are not expected to change.

## The scripts — the important part

**There are no `.psc` source files anywhere in the BSA.** There is no `scripts\source` folder. This
confirms what the author said: the source really is gone. Everything must come from decompiling the
56 `.pex` files.

The good news is that the compiled files carry a lot of recoverable information:

| property | value |
|---|---|
| format | Papyrus `.pex`, magic `0xFA57C0DE`, version **3.2**, game ID 1 |
| compiled | 30–31 December 2017 |
| built by | user `Danny` on machine `DANNY-PC` |
| original source names | **preserved**, with original capitalisation (e.g. `aaaFortPlayerQuestScript.psc`) |
| debug info | **present** |

Debug info matters a great deal. It keeps function names and line numbers, so a decompiler can
produce something close to the original rather than a mess of generated labels. Combined with the
preserved source filenames and their original casing, the decompiled result should be genuinely
readable and reasonable to work with.

### The largest scripts

These are where the behaviour lives and where any optimisation work will concentrate.

| script | size |
|---|---|
| `aaafortplayerquestscript.pex` | 46,233 B |
| `aaafortmainquestscript.pex` | 13,641 B |
| `aaafortstationaryguardscript.pex` | 8,649 B |
| `aaafortrandomquestscript.pex` | 7,832 B |
| `aaafortguardscript.pex` | 7,789 B |
| `aaafortbarracksscript.pex` | 7,597 B |
| `aaaforttutorialscript.pex` | 6,990 B |
| `aaafortwaterwellscript.pex` | 6,578 B |

46 KB of compiled Papyrus in a single script is very large. That one file is the main controller and
is the first thing worth reading once decompiled.

All 56 use the `aaafort` prefix, apart from two generated by the Creation Kit:
`qf_aaaforttutorialquest_01002853.pex` (quest fragments) and `tif__0100adbd.pex` (dialogue fragment).
